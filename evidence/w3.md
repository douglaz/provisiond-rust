## Implemented corrections

- OPS-49 claims belong to the surviving supervisor through registration. Caller cancellation in
  a genuinely pending COMMIT reply and at acknowledgment/registration leaves exactly one worker
  with its original capacity; no provider call starts for an unlearned result.
- OPS-21 cancellation covers licensing SQL, whole-transaction retry, sent COMMIT and handoff.
  Stops prevent another licensing transaction/provider entry; the original sent COMMIT retains
  its checkout/component owner until completion, transport death or process exit.
- A returned verified outcome is published before execution termination is acknowledged. A stop
  then records that outcome, preserving machine, ledger and commitment effects exactly once.
- The first absolute Stop-record deadline has a supervisor watchdog and transaction-loop checks.
  An absent/cancelled waiter cannot extend it, and late completion is not timely acknowledgment.
- OPS-11 live create cut-offs use actual first step-9 entry. Licensed but undispatched creates
  fail with retryable cut-off conflict, full commitment/exclusion release and no debit. Dispatched
  ambiguity and conservative ordinary restart remain distinct.
- One lock-loss observation owns fan-out and completion. Two observers cannot invent a later
  stop or reset an older bound. Healthy-store records land before nonzero lock-loss exit.
- Public engine-only methods require the private generation-checked transaction capability.
  API admission/payment stay unfenced; generation-first order and fatal supersession remain.
- REL-02 runs the real engine startup, without `--check-schema`, on missing schema/history,
  uninitialized, older, newer and incompatible-semantic cases; protected entry never begins.
- OVR-19's startup-lock keepalives have a separate explicit local assignment sharing pooled
  values: idle 2 s, interval 1 s, count 2. Invalid durations/counts are rejected; client socket
  getters and the actual lock session's server values are checked. D-6 remains Open for W8.

OPS-22 stop completion now distinguishes an acknowledged guarded effect from an acknowledged
zero-row refusal. Both end only that execution; the refusal emits `worker_zero_row` and
`landed=false`, leaving newer operation state, money and resource exclusion unchanged. Matching
claim numbers govern retirement. A pending record retains its own permit even when a newer claim
replaces its registry entry, and an observer that already captured it keeps its result. The
capacity fixture completes four claims/stops using three slots, retaining ownership until each
record's COMMIT reply arrives. Errors retain the original retry, deadline and exit behavior.

OPS-21/47 loss detection and user-stop registration share a short ordering mutex and the first
monotonic loss timestamp. Fan-out uses that timestamp; a true user stop after the detection log
exits as later even before registration. The existing observation mutex never blocks this exit.
Before detection, an earlier record keeps its exact deadline/identity and can land under a healthy
store. Concurrent observers remain idempotent; new claims and represented periodic admission
refuse after detection. No production periodic component was added.

The four store corrections, atomic payment/admission/verified-create primitives, ordinary restart,
component external-entry gates and original W1/W2 inventory remain covered. No real provider,
purchase or funds were involved. No W4 or expressly deferred workflow was added.
